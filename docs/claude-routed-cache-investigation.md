# Routed Claude cache regression investigation

Last updated: 2026-09-07

## Objective

Make a Claude Messages request physically routed to canonical Anthropic consume the same prompt-cache quota as native Claude Code while preserving routing, account selection, recovery, transport, and accounting behavior. Controlled warmed request comparisons already differ by only about 0.03 percentage points of cache-read share, with identical two-token raw input. A later Claude Code `Read` comparison exposed a separate caller-side admission mismatch: mapped routed requests used OpenCodex's local token estimate instead of Anthropic's exact `/v1/messages/count_tokens` result, so Claude Code admitted materially more tool output than native. Exact canonical token-count forwarding is now implemented and covered offline; a fresh laptop native-versus-routed `Read` comparison remains required before deployment.

## Safety constraints

- Never print or persist credentials, raw prompts, account identifiers, recipient data, or arbitrary headers.
- Never inspect, stop, restart, or modify `claude-wa` or `com.claude-whatsapp`.
- Controlled inference is authorized only on the laptop under the current goal and only through throwaway sessions.
- The laptop gateway may remain running only while the quota watcher is active; stop it immediately on a confirmed hard alert.
- Do not merge upstream, deploy elsewhere, commit, push, or delete branches without separate approval.

## Attempt 1: reconstructed request plus cache heuristics

Historical commits `8fa37f3cf` and `b98731f66` translated Anthropic Messages to Responses, reconstructed an Anthropic request, inferred a volatile system tail from block count, moved cache boundaries, and in one variant moved a system tail into message history.

### Proven failure

Affected routed requests repeatedly read only about 221,000–227,000 stable-prefix tokens while billing roughly 500,000–685,000 history tokens as uncached raw input. Most affected logical requests made exactly one physical send, excluding duplicate dispatch as the primary cause.

Two warmed native controls reached 98.12% and 96.96% post-warm cache-read share with no post-warm write above 10,000 tokens. This isolated routed reconstruction as the original regression path.

### Why it failed

The gateway guessed caller cache semantics from reconstructed structure. It had no provenance proving that the final system segment was volatile. The heuristic changed cache-marker placement and message roles for every affected translated Anthropic caller.

Upstream PR [#2939](https://github.com/lidge-jun/opencodex/pull/2939) was closed unmerged for the same reason. Only its separate stale-credential defect landed as PR #3005.

## Attempt 2: preserve the caller's Anthropic source wire

Commit `ad401e97c` retained the parsed Anthropic Messages body plus version/beta values as a private carrier. Eligible requests to exactly `https://api.anthropic.com/v1/messages` clone that body, replace the routed model and stream flag, normalize images, rebuild authentication/transport headers, and return before reconstructed cache-marker logic.

### What it fixed

The latest four-hour routed Opus sample contained only 38 raw input tokens across 10.40 million inclusive input tokens. This removed the prior repeated full-price raw-history pattern.

### Proven remaining failure

The same sample contained:

- 32 logical routed Opus requests.
- 56 physical attempts/sends and 24 recoveries.
- 2.46 million cache-read tokens.
- 7.94 million cache-creation tokens.
- 28.37% post-warm cache-read share.
- 15 of 15 measured post-warm writes above 100,000 tokens; maximum 553,558.

A cleaner historical sequence used one attempt/send, no recovery, and 7–18 second gaps. Cache reads stayed fixed at 122,957 while writes grew 195,008, 196,000, 210,133, and 212,493.

Across 4,948 cache-creation transitions with a prior successful request in the recorded session, 4,147 occurred on the same observed provider/model within five minutes; 4,060 simultaneously read an earlier prefix. This bucket represented 74.9% of creation-token volume.

This proves stable-prefix reuse plus repeated large-tail creation. It does not prove the exact first invalidating field.

### Why attempt 2 was not a complete solution

- Source replay is conditional. Ineligible requests silently use reconstructed Anthropic wire unless exact replay is required by a source-only feature.
- Route-driven effort normalization can delete `thinking` and add `output_config.effort`, making replay incompatible with a different target model.
- Vision preprocessing can disable source replay.
- Production telemetry did not record replay outcome, eligibility reason, account slot, branch lineage, cache-marker prefix fingerprints, image mutation, or version/beta cohort.
- Fake-upstream tests proved emitted request shape, not Anthropic backend cache reuse.
- Anthropic responses still round-trip through Responses events before returning as Messages SSE; whether that changes next-turn assistant history was not measured.
- Account stability cannot be inferred from existing ledgers because account labels are missing on all cache-creation rows.

## Attempt 3: strict canonical source lane

No third cache heuristic was added. Investigation first considered adding privacy-safe replay/account/lineage/prefix diagnostics because existing telemetry could not identify the first divergent field. The final transport trace found a smaller proxy-controlled boundary: canonical Anthropic responses still crossed Anthropic SSE to internal Responses events and back to regenerated Anthropic SSE before Claude Code persisted the assistant turn. Attempt 3 removes that round trip rather than adding the proposed diagnostic schema.

The strict lane now:

- Requires a compatible caller Anthropic Messages source whenever an Anthropic inbound request physically resolves to canonical `https://api.anthropic.com/v1/messages`.
- Fails closed with HTTP 400 before attempt creation, sidecars, image mutation, or physical dispatch when exact source replay is unavailable or incompatible.
- Preserves the caller's original `stream` value on the physical wire: SSE remains SSE and JSON remains JSON.
- Changes only the concrete routed model and permitted image representation; caller block order, tools/results, thinking signatures, redacted thinking, citations, and cache markers remain source-owned.
- Retains route selection, selected-account authentication, pre-output combo recovery, cancellation, physical-send accounting, usage inspection, and admission lifetime.
- Relays successful canonical Anthropic SSE and JSON body bytes directly. The stream inspector observes terminal state and usage without regenerating successful bytes.
- Requires `message_stop` for a successful SSE terminal. Root `error`, clean EOF before terminal, read failure, stall, or overflow are recorded as failures rather than false success.
- Preserves translated Responses behavior for noncanonical and non-Anthropic routes.

The proposed account slot, lineage digest, breakpoint digest, and correlation diagnostics were not implemented and must not be claimed as available. They remain a fallback investigation tool only if a controlled same-account comparison fails despite this strict lane.

This proves that attempt 3's routed source wire reused a native-created prefix on the same Anthropic account. It does not waive the remaining transport-review and offline gates.

### Organic rollout incident and monitor correction

`ocx start` was incorrectly treated as an isolated launcher. It globally synchronized routing for existing laptop sessions, causing one parent session and its subagents to generate 306 requests in about ten minutes. The gateway was stopped and its monitor canceled. No Mini or `claude-wa` process was changed.

The first monitor also applied Anthropic's 90% cache-read threshold to Terra. Provider-aware policy now limits low-read, high-write, high-raw, and falling-read cache alerts to canonical Anthropic providers. Terra remains observable but neutral. Durable analytics and the GUI use the same rule; Terra-only history can no longer render as green Anthropic-clear status.

### Organic cache-TTL false positive

The laptop watcher later stopped the gateway after two full cache creations, but that stop did not confirm a gateway cache leak. Both writes followed idle gaps longer than Anthropic's default five-minute ephemeral cache lifetime: 794,667 tokens after 1,097.1 seconds and 808,953 tokens after 568.2 seconds. Each request used one physical send, reported two raw input tokens, and recorded no recovery or failover. Each immediate follow-up then read the recreated prefix (794,667 and 808,953 tokens respectively).

The confirmed defect was shared monitoring state: both the watcher and durable analytics retained `warmed` and prior-read state forever. They therefore compared a new cache lifetime with an expired one and emitted `high-cache-write-after-warmup`, `low-cache-read-share-after-warmup`, and `falling-cache-read`. Sequence state now expires after five minutes of inactivity; retry, recovery, repeated-send, and combo-failover alerts remain unconditional. A durable regression reproduces the sanitized 568.2-second sequence and also proves that consecutive-high-raw state cannot cross the idle boundary.

### Decision rule

1. If the controlled native-versus-routed comparison passes, accept the strict lane; no extra cache diagnostics are needed.
2. If it fails while every request uses one send and exact source replay, add the privacy-safe account/lineage/breakpoint diagnostics before changing transport again.
3. If body, cache markers, account, model, headers, and timing then match while Anthropic still rewrites the tail, local rewriting is excluded; use Anthropic cache diagnostics/correlation rather than another proxy mutation.
4. Canonical Anthropic must never silently fall back from source replay to reconstructed wire. It must use the compatible strict source lane or fail closed before a physical send.

## Acceptance gates

## AgentRadar long-context follow-up

A corrected transcript-to-ledger join produced 210 top-level assistant usage rows but only 183 unique `message.id` calls. The 27 duplicates repeated one call's usage across assistant content blocks. After deduplication, the gateway recorded exactly 183 physical attempts and 183 sends: every matched main-session call used one send. All rows belonged to one root transcript and one non-sidechain CLI session. Raw input remained exactly two tokens, so the quota burn came from cache creation rather than raw history or duplicate dispatch.

The caller-model sequence was contiguous, not interleaved: calls 0–166 were 167 `combo/waterfall` calls and calls 167–182 were 16 `claude-opus-5` calls. The earlier 164/19 count is superseded: assistant response metadata reported the physical `claude-opus-5` model during artifact calls 147–149 because strict relay preserves Anthropic's response bytes, but the caller still requested `combo/waterfall`. Physical providers rotated in four contiguous segments (`P1`, `P2`, `P3`, then `P1`), excluding random per-call provider switching as the explanation. Among same-provider transitions inside five minutes, 120 cache reads were exactly 99,719 tokens, four were zero, and one was 103,032. Eleven subagents were spawned, but they do not account for the 183 main-lineage calls; sanitized transcript references to Paperclip or E2E likewise do not prove separate physical sends.

The decisive structural correlation was the preceding user record. Excluding the artifact window and the first observation, all 111 old-path calls immediately following a tool result stayed on the same physical provider and completed inside five minutes; 109 read exactly 99,719 tokens and two read zero. None reused the full prior prefix. By contrast, 21 old-path calls following a non-tool user or system record did achieve full reuse. During the artifact window, the first two tool-result continuations moved from a 103,032-token partial read to a 641,812-token full read. After rollback, every observed tool-result continuation returned to the 99,719-token floor. In the final direct caller-model arm, all nine tool-result continuations reused the full prior prefix. This isolates the dominant historical failure to the old combo tool-loop boundary rather than request rate, provider rotation, retry, raw input, or general server-side intermittency.

### Proven source-replay deployment window

Deployment lifecycle output and newly present `firstSendAt`, `promptCacheTtlMs`, and source-replay-era telemetry prove the tested package was active for combo calls 147–149. All three used the same physical provider alias, had a five-minute effective TTL, did not overlap, and used one send:

- Call 147: 611,083 inclusive, 2 raw, 0 read, and 611,081 written.
- Call 148: 641,814 inclusive, 2 raw, 103,032 read, and 538,780 written.
- Call 149: 643,950 inclusive, 2 raw, 641,812 read, and 2,136 written.

The first artifact call warmed the request. The second still retained only a 103,032-token prefix. The third reused the whole prior cacheable request. This proves strict source replay can achieve native-like reuse on `combo/waterfall`; it does not prove replay alone eliminates recurring rewrites.

The deployment then failed readiness verification and rolled back, after which calls 150–166 lost the new telemetry and mostly returned to the 99,719-token read floor. Call 155 was an important exception: it read 622,387 tokens and wrote only 591 despite lacking artifact-era telemetry. Full reuse therefore also occurred once on old or otherwise unproven code. The failure is intermittent, not a permanent inability of either wire path to cache.

### Native caller-model arm

Call 167 switched the caller-visible model from `combo/waterfall` to `claude-opus-5`, forcing one legitimate cold lineage: 666,496 inclusive, 2 raw, 0 read, and 666,494 written. Calls 168–178 then reused nearly all prior cache and wrote only appended growth. Call 179 arrived about 7 minutes 27 seconds later, read zero, and wrote 688,622, consistent with natural five-minute TTL expiry. Calls 180–182 warmed and reused normally again.

A forced local four-call ToolSearch capture found no recurring custom-model mutation. Both caller-model arms used the same top-level fields, adaptive thinking, high effort, context-management field, beta set, marker-movement policy, message/block progression, one-time ToolSearch expansion, and stable tool set afterward. Within each arm, system hashes stayed constant, tool hashes changed only once when ToolSearch expanded tools, and prior message-prefix hashes remained stable except for expected final-message marker movement. Differences were caller-model-owned: `max_tokens` was 32,000 for `combo/waterfall` and 64,000 for `claude-opus-5`; initial system text and model-specific `Agent` and `Bash` schemas also differed. Switching model names therefore changes Claude Code's generated request contract and legitimately resets cache, but the short capture did not reproduce repeated combo-specific churn.

Native Claude Code reports show similar long-context tail rewrites without OpenCodex: [#87966](https://github.com/anthropics/claude-code/issues/87966), [#91514](https://github.com/anthropics/claude-code/issues/91514), and [#82563](https://github.com/anthropics/claude-code/issues/82563). These comparisons exclude OpenCodex as a necessary cause but do not identify the real AgentRadar invalidating field.

### Existing native-shaped routing mechanism

No source change is needed to preserve the caller-visible model identity. Existing `claudeCode.modelMap` maps inbound `claude-opus-5` to `combo/waterfall`, so Claude Code generates its native Opus system/tool contract while OpenCodex still selects the ordered combo. Every combo target must use the Anthropic adapter, the exact canonical Messages URL, and a compatible physical `claude-opus-5` model for source replay. Mapping makes native passthrough intentionally ineligible for that model; configuration cannot provide both true caller-credential passthrough and combo routing for the same inbound literal model on the same turn.

### Caller-side `Read` admission and exact token counting

A deterministic local Claude Code probe asked the same installed CLI to `Read` one fixed file through a fake non-egressing Anthropic server. The native caller-visible `claude-opus-5` contract admitted 401 lines (50,124 raw characters; 51,620 serialized characters). Calling the custom `combo/waterfall` model admitted 675 lines (84,374 raw characters; 86,966 serialized characters). Mapping caller-visible `claude-opus-5` to the combo improved the result to 590 lines (76,001 characters), but remained materially above native.

The remaining difference occurred before `/v1/messages`. Claude Code 2.1.260 asks `/v1/messages/count_tokens` before admitting large tool results. Native Claude Code receives Anthropic's exact tokenizer. OpenCodex previously returned its local character-ratio estimate for every mapped model, including a combo that would physically select canonical Anthropic. Model mapping therefore fixed the caller-generated request contract but could not make `Read` sizing native-equivalent.

The mapped count path now resolves the concrete physical route first. If the final adapter and URL are exactly canonical Anthropic, it validates exact source replay before authentication or dispatch, resolves the selected provider/account credential, replaces the mapped/combo model with the concrete Claude model, builds the trusted Anthropic request, and sends it to `https://api.anthropic.com/v1/messages/count_tokens` over a fresh connection. Caller admission credentials and arbitrary headers are never forwarded. Source/configured/mandatory beta values and the source Anthropic version retain the same semantics as generation requests. Upstream status, body, content type, and `Retry-After` are relayed directly. Count calls create no generation-attempt or send telemetry. Noncanonical Anthropic-compatible and non-Anthropic routes retain local estimation.

Failing-first coverage proved that the old mapped path returned local HTTP 200 instead of a mocked canonical Anthropic HTTP 429. Durable endpoint regressions now cover exact route/auth/header/error relay, noncanonical local estimation, incompatible canonical no-dispatch, translation-buffer overflow before dispatch, client cancellation, fresh transport, and absence of generation telemetry. Both the translated body and final serialized adapter body count against the shared 32 MiB translator budget; overflow returns deterministic HTTP 413 with `translation_buffer_limit`.

Current evidence isolates the dominant historical root boundary to old combo tool-result continuations and the latest controlled `Read` mismatch to local count estimation. Strict source replay and exact canonical token counting now remove both proxy-owned differences. A fresh installed-package laptop comparison must still prove that routed `Read` sizing and resulting raw input match native before the package can be deployed to the Mini.

## Unexpected-burn investigation, 2026-09-15

### Confirmed root causes

Three separate effects were measured on the live Mini ledger (72h, 17,265 rows) and on controlled laptop sessions. They are independent; only the first is a gateway code defect.

1. **Codex account exhaustion was classified as a transient server error.** The ChatGPT Codex backend reports a depleted plan window as HTTP 502 `upstream_server_error` carrying the prose `The usage limit has been reached`, never the documented HTTP 429 `usage_limit_reached`. `isProviderScopedQuotaCap` matched only `monthly usage limit reached` on 429, so the exhausted target took the generic `target` scope and the 60-second default cooldown. 942 doomed sends in 72h (847 `openai`, 95 `combo`), each surfacing to the caller as `adapter_eof`, plus 94 downstream `503 No available targets for combo: waterfall`. The same near-miss existed in `isTransientRequestRateLimit`, whose exclusion list read `usage limit reached` while the wire says `usage limit has been reached`.

2. **Combo failover to Astra multiplies raw input.** `combo/waterfall` targets `anthropic/claude-opus-5` then `openai/gpt-6-astra`. When Anthropic is cooling, long Claude histories are re-sent to Astra, which sustains roughly 32% cache-read share against Anthropic's 96%. All 2,362 high-raw rows in the sample were `combo -> openai`; none of the 1,982 `combo -> anthropic-pa7bca0` rows exceeded 100k raw. This is provider behaviour, not a translation defect, but it is why Codex quota drained.

3. **Claude Code inlines every MCP tool schema when `ANTHROPIC_BASE_URL` is set.** Controlled single-turn measurement on identical prompt, cwd, and tool set (218 tools native, 217 through the gateway):

   | | native | gateway | delta |
   |---|---|---|---|
   | MCP disabled | 38,749 | 42,416 | +3,667 |
   | MCP enabled | 43,236 | 103,158 | +59,922 |

   A wire capture (sizes only) shows the client posting 217 tool definitions totalling 224,077 bytes (~56k tokens) to a custom base URL; `mcp__posthog__exec` alone is 36,393 bytes. Natively the same tool set costs 4,487 tokens, so the official endpoint is not receiving inline schemas. Answering the client's `/api/hello` and `/v1/models` probes with an explicit capability/beta advertisement did not change the payload (196 tools, 204,389 bytes still inlined), so no gateway-side capability signal was found that restores deferred tool loading. This is client behaviour triggered by the custom base URL, and on an MCP-heavy machine it is the dominant native-versus-gateway quota difference: 2.4x input per session.

## Tool search: the actual fix for the MCP inflation, 2026-09-16

Finding 3 above (Claude Code inlining every MCP tool schema for a custom base URL) is documented client behaviour with a documented override, not an unavoidable cost. Claude Code defers MCP tools and discovers them on demand by default, but auto-disables tool search when `ANTHROPIC_BASE_URL` is a non-first-party host, because most proxies do not forward `tool_reference` blocks. `ENABLE_TOOL_SEARCH=true` overrides that.

The strict canonical replay lane is exactly what the feature needs: it forwards the caller's Anthropic body verbatim and relays Anthropic's response bytes verbatim, so `tool_reference` survives untouched. Measured on this machine, same prompt, same 217 MCP tools, turn-0 inclusive input:

| Arm | Turn-0 inclusive |
|---|---|
| Gateway, tool search off (previous behaviour) | 103,158 |
| True native | 43,236 |
| Gateway, tool search on (isolated build) | 35,619 |
| Gateway, tool search on (live laptop gateway) | 33,984 |

A 65% reduction that also puts the gateway below native, with every MCP server still attached. End-to-end proof rather than a token count: a session asked for a search, the transcript shows `ToolSearch` firing and then `mcp__perplexity__perplexity_search` executing and returning the right answer — a tool that was never in the initial prompt. Verified on both `claude-opus-5` and `combo/waterfall`.

The Astra leg was not live-tested: an isolated `CODEX_HOME` has no native profile, so the request is fenced by the native-main startup gate with HTTP 503. Static reading says it degrades safely rather than failing — `src/adapters/openai-responses.ts` strips `defer_loading` and promotes deferred tools, and `src/responses/tool-search-compat.ts` rewrites a `tool_search` tool into a plain `function` — so Astra falls back to inlining: no saving, no error.

## Inlined MCP tools and cache rewrites, 2026-09-19

Finding 3 above measured inlined MCP schemas as a per-turn size cost. A live Mini session on 2026-09-18/19 showed the second cost: a gateway session started without `ENABLE_TOOL_SEARCH` (its launch path predated the recipe change, so the variable was absent from its environment) accumulated 1,006 `falling-cache-read` alerts and 120M cache-write tokens on `claude-opus-5`, at roughly 500–760k inclusive tokens per request with near-zero output.

After the same session was restarted with `ENABLE_TOOL_SEARCH=true`, the first 8 minutes recorded 168 requests, 0.96 cache-read share, and one rewrite event (~100k excess write), with per-request context at 51–125k.

Mechanism (inferred, not isolated): tool definitions lead the cached prefix, so any change to an inlined MCP tool array — a server reconnecting, a tool appearing or disappearing — invalidates the entire cache behind it. With tool search the MCP tools are deferred and the prefix stays stable. The before/after comparison is confounded by the restart also dropping the accumulated context, so treat it as strong correlation rather than proof.

Operational consequences now in place:

- `ENABLE_TOOL_SEARCH=true` is set in `~/.claude/settings.json` `env` on both hosts, so it applies to every launcher, not only the `agent` recipe.
- The life-wiki orchestrator sets `ENABLE_TOOL_SEARCH=true` and routes its `claude -p` spawns through the gateway.
- Mixing models on one large context compounds the cost: the cache is per model, so every Opus⇄Fable switch or combo failover rewrites the whole prefix cold (observed: 558,865 written, 0 read, on a Fable leg).
